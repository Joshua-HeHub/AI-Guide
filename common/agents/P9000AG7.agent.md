## 编译与构建

**刷机验证/正式 HPM 产物的正确编译方式**：必须使用 `iec_build.sh`，因为它在 `git-spx-beta9.3 buildsrc` 后会自动执行 `ImageSigningTool`，把 `rom_enc.ima` 替换为 `rom.ima`，并继续生成 `tools/generatehpmimagetool/HPM_FW/bmc.hpm`。单独执行 `git-spx buildsrc` 只适合源码编译检查，不能作为刷机/HPM 验证产物。

```bash
# Base 编译 + 签名 + HPM 打包
cd /bmc/joshua/P9000AG7 && ./iec_build.sh -b configs/Quartz.PRJ

# workspace 切换分支后首次编译，或怀疑旧 workspace 污染时，使用干净重编
cd /bmc/joshua/P9000AG7 && ./iec_build.sh -r -b configs/Quartz.PRJ
```

> ⚠️ `-r` 会删除 `workspace/` 和 `spx-packages-links/`，使用前必须确认不需要保留旧 workspace 内容。
> ⚠️ `build.sh` 依赖 `/data01/AMI_GITSPX_LICENSE/.gitspxcache`（Docker License），该文件在此机器上**不存在**，会直接报错退出，**不要使用**。

**仅做源码编译检查时**，才可直接调用系统 `git-spx`：

```bash
cd /bmc/joshua/P9000AG7 && sudo git-spx buildsrc ./configs/Quartz.PRJ ./packages workspace
```

这种方式不会执行 `ImageSigningTool`，也不会保证生成可用于 OOB/HPM 升级验证的最终镜像。

## shell 命令和问题分析规则

1. **优先使用 `rtk`**：执行 shell 命令时优先使用 `rtk` 前缀，以减少大输出进入上下文。
2. **无专用子命令时**：对 `rtk` 没有专用子命令的场景，使用 `rtk run '<command>'` 或 `rtk proxy <command>`。
3. **禁止直接读取大文件**：不要直接读取完整 log、dump、构建输出；必须用 `grep` / `tail` / `head` / `sed -n` 等方式缩小范围。
4. **优先摘要分析**：优先用命令过滤、摘要和定位关键行，不要把全量数据直接读入上下文。

## HPM 打包

常规刷机验证不要手工从 `workspace/Build/output/rom.ima` 打 HPM，优先使用 `iec_build.sh -b configs/Quartz.PRJ` 生成 `tools/generatehpmimagetool/HPM_FW/bmc.hpm`。手工打包只用于确认 HPM 工具或做临时补救：

```bash
cd /bmc/joshua/P9000AG7/tools/generatehpmimagetool/ && 
sudo cp /bmc/joshua/P9000AG7/workspace/Build/output/rom.ima ./FW/rom.ima && 
sudo ./CreateHPMImage create ./Conf/bmc_image.conf

# DPU
./CreateHPMImage create ../SampleConf/bmc_dpu_image.conf
```

`iec_build.sh` 已经生成 `tools/generatehpmimagetool/HPM_FW/bmc.hpm`，OOB 验证时直接调用更新工具即可。账号按目标 BMC 当前版本选择：1.06/字节分支通常使用 `toutiao/<BMC_PASSWORD>`，1.07 及以后白牌分支通常使用 `ADMIN/<BMC_PASSWORD>`。

```bash

cd /bmc/joshua/P9000s/fw_update_tool && ./OobUpdate.sh -H 172.17.8.118 -U toutiao -P '<BMC_PASSWORD>' -F /bmc/joshua/P9000s/P9000AG7/tools/generatehpmimagetool/HPM_FW/bmc.hpm -T BMC -S
```

> ⚠️ 更新前必须确认 `bmc.hpm` 来自 `iec_build.sh` 或等效的签名 + HPM 打包流程；单纯 `git-spx buildsrc` 后手工临时打包的 HPM 不能直接作为 OOB 验证依据。
