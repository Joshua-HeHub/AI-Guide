# 在线实测避坑（通用）

按需读取：仅在需要对在线机台做触发路径验证、报文注入、计数差分或内核动态追踪（ftrace 等）时读取。领域术语分级（静态门禁分析 / 只读运行态核验 / 路径可达性实测 / 效果复现）统一见根目录 `GLOSSARY.md`。

## 1. 实验设计：先定增量归属，再动手

1. **先取基线，后触发**：任何看增量的实测（计数器/trace/日志），触发前先取目标侧基线，触发后重读差分。
2. **先建对照组，再查目标特殊路径**：目标无响应时先做最小对照实验（如普通 `ping`/`ping6`）排除底层连通性，把“环境不通”与“输入不对”分开。
3. **输入没反应时，先查探针自身构造**：格式差一个字段或扩展头长度差两字节就会被内核前端丢弃。用错误类计数器（如 `Ip6InHdrErrors`）差分快速区分“被丢弃”与“未到达”。

## 2. 证据有效性：选对观察点，交叉印证

1. **观察点必须绑定当前配置下实际生效的子系统路径**：同一协议行为在不同内核配置下会走不同钩子（如启用 Netfilter/conntrack 提前重组时会绕过标准 `ipv6_frag_rcv` 与 `Ip6Reasm*` 计数使其恒为 0）。读到 0 时先核对源码执行路径，再用至少两个独立信号交叉印证。
2. **区分“入口命中”与“深层分支命中”**：协议分发前自增的计数器只证明到达入口，不单独证明目标函数内部走进深层脆弱分支；需要内部调用链实证时，再挂对应 `function_graph` 或深层探针。
3. **动态过滤名单先查后用**：写 `set_ftrace_filter` 等前先查 `available_filter_functions`；写入不存在的符号会以 `EINVAL` 静默中断后续整条命令链。
4. **防背景流量回绕覆盖**：抓窄窗口证据前先扩采集 buffer（或缩小过滤面），收尾必须恢复默认值。

## 3. 前置确认与状态恢复（强制闭环）

1. **区分“硬阻塞”与“软阻力”，单点受阻不得整项停工**：会引发崩溃/断网的高危测试先落实恢复入口；离线自校验、只读核验及其他平台验证继续推进。
2. **内网离线缺第三方工具时，优先标准库最小实现或既有合规容器能力**：不在 PyPI/GitHub 超时上空转；简单协议/报文用标准库手写并加离线自校验；本机缺特定权限时盘点最小权限一次性容器能力（如 `--cap-add NET_RAW`）。
3. **每步前置状态机器可判定确认后再走下一步**：准备动作（arm tracer/切换模式）末尾拼回读状态 + 显式成功旗标，输出不匹配即拒绝执行主动作。
4. **单条远端命令是独立 shell**：依赖 `cd`/环境变量的动作必须拼在同一条命令串或通过 `scripts/bmc_exec.py --script-file` 执行。
5. **恢复以终态回读为准**：实验修改（tracer/buffer/过滤器/临时配置）结束前，回读所有被改项的最终值作为恢复证据。

## 4. 流程编排与输出核对

1. **多步流程拆成多次单命令调用**：优先使用 `scripts/bmc_exec.py`（支持 `--cmd` / `--script-file` / `--tee-log`），避免多层嵌套 `bash -c` 引号经包装器转义碎裂。
2. **关键动作输出必须落盘**：发包或关键写操作必须 `tee` 落盘（或 `--tee-log`），以日志文件为准核对，不凭终端显示片段猜测。超长输出转存临时文件后，只用 `grep` 提取关键旗标与计数器行。
3. **以业务输出和远端退出码为准**：使用 `scripts/bmc_exec.py` 可自动关闭通道避免 paramiko `BufferedFile.__del__` 噪音；遇到非业务层的连接关闭 warning 不当作执行失败盲目重试。
