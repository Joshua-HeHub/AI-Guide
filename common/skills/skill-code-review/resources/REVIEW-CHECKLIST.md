# 代码审查检查清单

## 高优先级

- 功能正确性：实现是否满足预期，是否漏掉主路径或关键分支。
- 回归风险：是否破坏现有调用方、协议、配置、兼容性或已有流程。
- 安全性：输入校验、认证授权、命令执行、路径访问、敏感数据处理是否安全。
- 资源与状态：内存、文件句柄、锁、会话、引用计数、生命周期是否正确。
- 并发与时序：竞态、重入、重复执行、超时、异步回调顺序是否会出错。

## 中优先级

- 错误处理：失败路径是否可控，返回值和异常是否被正确处理。
- 日志与可观测性：关键失败是否有足够日志，是否方便后续定位。
- 测试覆盖：主路径、失败路径、边界条件、回归点是否有测试或验证方法。
- 性能：是否引入不必要的循环、重复 I/O、锁竞争、阻塞等待或高复杂度路径。
- 配置影响：默认值、开关项、编译条件、环境依赖是否会导致行为偏差。

## 低优先级

- 可读性：命名、函数长度、控制流复杂度是否影响理解。
- 可维护性：重复逻辑、隐式假设、硬编码、耦合是否偏高。
- 注释与文档：说明是否过时、缺失或与实现不一致。
- 代码风格：是否明显偏离项目惯例并影响后续维护。

## 常见追问

- 这个修改在空输入、非法输入和极端输入下会怎样？
- 调用失败后，状态是否还能恢复？
- 有没有旧调用方会因为接口或语义变化而出问题？
- 如果用户重复点击、重复请求或并发进入，结果是否稳定？
- 是否补了最关键的一条回归测试？
