# 审查问题交叉验证

在最终报告前，对主审查识别出的全部候选问题进行第二轮验证。

## 双验证者流程

1. 并行调用两个独立子代理。
2. 每个子代理接收完整的候选问题列表，并独立读取相关代码上下文。
3. 每个验证者逐项检查：
   - 问题是否真实存在。
   - 新版本行号是否准确。
   - 严重级别是否合理。
   - 是否因为上下文不足而误报。
4. 每个验证者返回所有问题的验证结果：

```json
[
  {
    "issue_id": 1,
    "exists": true,
    "severity": "major",
    "reasoning": "错误路径未释放已分配对象"
  }
]
```

## 共识规则

| 确认数 | 置信度 | 最终处理 |
|---|---|---|
| 2/2 | High | 纳入报告 |
| 1/2 | Medium | 纳入报告并说明分歧或上下文限制 |
| 0/2 | Low | 作为误报排除 |

被排除的问题及原因保留在内部验证记录中，不进入用户报告。

## 降级方案

子代理不可用时，主代理必须以全新视角重新读取每个问题的代码上下文，重新核对存在性、行号和严重级别。无法确信的问题从最终报告中移除。
