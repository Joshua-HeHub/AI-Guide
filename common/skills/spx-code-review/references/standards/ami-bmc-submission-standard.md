# AMI BMC 代码提交规范

> 来源: 用户提供的《AMI BMC代码提交规范》Word 文档
> 版本: 1.0
> 日期: 2023-03-09

## 适用范围

本文档规范固件 BMC 开发中的代码提交要求。所有提交都必须遵循本规范。

## 提交规则

### 1. 按模块提交

代码必须分模块提交。提交信息必须清楚描述变更内容；如果英文无法准确描述，使用中文说明。

### 2. 标题格式

标题格式必须为：

```text
[项目名][客户][RR13-BMC]：内容
```

项目名、客户、`RR13-BMC` 和实际变更内容都应明确，不应使用空泛标题。

### 3. Bug 修复提交

Bug 修复提交的 `Description` 必须包含问题原因、解决方案、测试步骤和测试结果：

```text
Description:
    问题原因:
        1. ...
    解决方案:
        1. ...
    测试步骤:
        1. ...
    测试结果:
        1. ...

Tracker: #Num
```

### 4. 新功能或功能修改提交

新功能或功能修改提交的 `Description` 必须包含变更描述、测试步骤和测试结果：

```text
Description:
    变更描述:
        1. ...
    测试步骤:
        1. ...
    测试结果:
        1. ...

Tracker: #Num
```

## 审查时的核对要求

- 检查 commit 标题是否符合格式，且项目名、客户、组件和变更内容清楚。
- 根据提交性质确认使用了 Bug 修复模板或新功能/功能修改模板。
- 检查 Bug 的问题原因和解决方案是否对应，不能只有结论没有说明。
- 检查测试步骤和测试结果是否一一对应；代码审查不能把未提供的实测结果推断为通过。
- 检查是否提供 `Tracker: #Num`。
- 提交信息缺失时，在 Review 事项汇总相应行填写“当前项有风险”、标记 `X` 并关联 `风险确认 #N`，说明缺失信息；是否阻塞合入由项目门禁决定，不将其误报为代码逻辑缺陷。概览中的“待提供”或“未检查”仅表示证据进度，不能代替该风险记录。
