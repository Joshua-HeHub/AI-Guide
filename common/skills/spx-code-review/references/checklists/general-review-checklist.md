# 通用代码审查清单

## 安全性

- [ ] 所有网络和外部输入是否校验类型、长度、格式和范围？
- [ ] 是否存在命令注入、Shell 拼接、路径遍历或用户可控格式化字符串？
- [ ] 是否硬编码密码、Token、密钥或在日志/API 响应中泄露敏感数据？
- [ ] 受保护端点和 IPMI 命令是否在处理前完成认证与授权？
- [ ] 网络协议结构体是否使用固定宽度类型并显式处理 padding、对齐和字节序？

## 性能与长期运行

- [ ] 长驻 daemon 是否存在内存、日志、队列或缓冲区持续增长？
- [ ] 计数器、偏移和时间计算是否可能在长期运行中溢出？
- [ ] 线程或进程创建是否有上限？
- [ ] 递归或大局部数组是否可能导致栈溢出？
- [ ] 阻塞 I/O 或硬件访问是否阻塞关键请求线程？
- [ ] 高频 I2C/SPI 读取或资源创建销毁是否需要缓存或池化？

## 正确性

- [ ] 空值、空数组、空字符串、零值、负数、最大值和 off-by-one 是否正确处理？
- [ ] 系统调用、库函数和硬件访问的返回值是否检查？短读、短写和部分成功是否处理？
- [ ] 错误路径是否保持状态一致并释放已经取得的资源？
- [ ] 并发读写、信号处理和跨进程共享状态是否安全？

## 可维护性

- [ ] 命名、日志和注释是否与实际行为一致？
- [ ] 新增或修改函数是否说明用途、输入参数、输出参数和返回值？
- [ ] 是否引入死代码、魔鬼数字、重复逻辑或不必要的全局状态？

## 测试

- [ ] 正常路径、失败路径和关键边界是否有测试？
- [ ] Bug 修复是否包含可复现原问题的回归测试？
- [ ] 长驻 daemon、异常流量和网络输入是否需要压力测试或 fuzz？
- [ ] 测试结果是否与提交描述中的步骤一一对应，且断言能证明预期行为？
