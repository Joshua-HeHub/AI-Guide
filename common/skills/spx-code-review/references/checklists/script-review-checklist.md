# Python 与 Shell 脚本审查清单

## Python

- [ ] 禁止将外部输入拼接到命令中，调用子进程时避免 `shell=True`。
- [ ] 异常处理是否使用具体异常类型，是否避免无说明的 `except:` 或吞掉错误？
- [ ] 文件和网络操作是否处理打开、读写、关闭及异常路径？
- [ ] 是否使用项目 logging 设施而不是不可控的 `print`？
- [ ] 错误是否带足够上下文记录，同时避免泄露凭证和敏感数据？
- [ ] 长驻脚本中的线程、子进程、文件描述符和临时文件是否正确回收？

## Shell

- [ ] 变量展开是否正确引用，例如使用 `"$var"`？
- [ ] 脚本是否按项目要求启用错误退出和 `pipefail`，并正确处理预期失败命令？
- [ ] `rm -rf`、`cp`、`mv`、重定向等路径操作是否验证空值、根目录和通配符展开？
- [ ] 临时文件和目录是否使用 `mktemp` 安全创建并在退出时清理？
- [ ] 外部输入是否可能形成命令注入、参数注入或路径遍历？
- [ ] 管道、命令替换和后台进程的返回值是否检查？

## 报告要求

引用具体脚本和行号，区分可利用的命令注入、确定性逻辑错误和项目风格问题。不要仅因未使用某个 Shell 选项而阻塞合入，应结合脚本调用方式和错误处理判断实际风险。

## 严重级别参考

- 可由外部输入触发的命令注入或任意文件删除：`[CRITICAL]`。
- 静默失败、错误路径资源泄漏或不可恢复的文件操作：`[MAJOR]`。
- 日志、可维护性或防御性增强：`[MINOR]`。
