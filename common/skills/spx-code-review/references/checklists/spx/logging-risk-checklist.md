# SPX 日志转储风险检查

## 触发条件

仅当 diff 涉及日志缓冲区、队列、转储、轮转、发送、重试、清理或日志对象内存所有权时执行详细检查。未命中时在 Review 事项汇总中标记为 `已检查-不涉及`。

## 检查步骤

- [ ] 日志生产速度超过转储速度时，队列或缓冲区是否有明确上限和背压策略？
- [ ] 转储目标不可用、磁盘满、网络失败或权限错误时，日志对象是否仍能释放？
- [ ] 重试是否有限制，失败日志是否会重复入队或无限复制？
- [ ] 轮转、删除和压缩失败是否造成文件或内存持续累积？
- [ ] 多线程日志队列的所有权和并发清理是否安全？
- [ ] 日志内容和格式化过程是否泄露敏感数据或造成超大分配？

## 证据与报告

代码命中且检查无风险、证据完整时标记为 `已检查-无风险`。发现积压/泄漏风险或缺少必要运行证据时标记为 `当前项有风险`，并包含：

- 触发代码位置和可能的积压/泄漏链路。
- 队列或缓冲区上限、失败清理策略。
- 转储失败、磁盘满或下游不可用场景的运行证据。

缺少运行证据时必须在风险原因中写明待补充材料，不得标记为 `已检查-无风险`。

## 严重级别参考

- 可持续耗尽 BMC 内存或存储并导致服务不可用：`[MAJOR]`；可由未认证网络输入触发时可提升为 `[CRITICAL]`。
- 有界丢日志、告警不足或低风险轮转问题：`[MINOR]`。
