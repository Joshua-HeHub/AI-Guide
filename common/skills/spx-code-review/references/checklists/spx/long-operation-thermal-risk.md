# SPX 部件升级与长时操作散热风险检查

## 触发条件

出现以下任一变更时，必须执行本检查：

- 新增或修改 BIOS、CPLD、PSU、NIC、背板、存储、风扇控制器或其他部件的固件升级、烧录、擦除、校验、回滚操作。
- 新增或修改可能长时间占用 I2C、SPI、JTAG、GPIO、串口、共享总线、设备锁或工作线程的硬件访问。
- 新增或修改长时间诊断、压力测试、校准、扫描、重试、等待设备就绪或同步阻塞流程。
- 操作期间可能暂停 Sensor 轮询、延迟温度更新、重启监控进程或使温度设备暂时不可访问。

未涉及部件升级或长时操作时，在 Review 事项汇总中标记为 `已检查-不涉及`。

## 温度数据新鲜度

- [ ] 明确操作的正常时长、最大时长、超时和重试上限，不能存在无界等待。
- [ ] 操作是否占用温度 Sensor 使用的总线、锁、线程或事件循环，导致采样无法按周期执行？
- [ ] Sensor 缓存是否带时间戳、有效期或 stale 标志，超过更新周期后是否停止把旧值当作实时温度？
- [ ] 温度长时间未更新时，是否显示 `No Reading` 或明确的 stale 状态，而不是继续显示旧的正常值？
- [ ] 升级过程中设备重启、下线或地址变化时，相关温度 Sensor 是否及时失效并在设备恢复后重新发现？
- [ ] 多个温度来源中某一路中断时，是否能使用可靠冗余来源，且不会以默认值 0 或未初始化值替代？

## 临时散热与 Fail-safe

- [ ] 操作开始前是否进入配套的临时散热策略，例如提高最低 PWM、固定安全风扇档位或切换备用温度源？
- [ ] 临时策略是否覆盖整个升级/长时操作窗口，包括准备、擦写、校验、设备重启、重新枚举和失败回滚？
- [ ] 温度数据过期、读取超时、`No Reading`、监控线程阻塞或升级异常时，是否立即进入 fail-safe，而不是维持低风扇转速？
- [ ] fail-safe 的风扇转速、功率限制、降频或保护关机条件是否与部件功耗和 Thermal 设计一致？
- [ ] 操作进程 crash、被取消、超时或 BMC 服务重启时，是否仍能保持安全散热，避免清理逻辑未执行就退出临时策略？

## 恢复与并发

- [ ] 只有在操作结束、设备重新可访问、连续取得规定次数的有效新温度后，才退出临时散热策略？
- [ ] 退出策略时是否清除 stale/`No Reading` 状态并重新计算告警、Health LED 和 thermal zone？
- [ ] 升级失败或回滚后是否恢复 Sensor 轮询、锁、定时器、线程和风扇策略？
- [ ] 多个升级或长时操作并发时，临时散热请求是否引用计数或按最高策略聚合，避免一个操作结束后提前降速？
- [ ] AC Cycle、host power cycle 或用户取消与操作并发时，散热状态是否保持一致？

## 测试与证据

- [ ] 提供正常操作期间的 Sensor 更新时间戳、读值和风扇 PWM/转速记录。
- [ ] 注入总线占用、Sensor 超时、设备重启、操作超时、失败回滚和进程异常退出，验证 fail-safe 生效。
- [ ] 验证操作结束后 Sensor 恢复更新、告警/Health LED 重算且散热策略不会过早退出或永久保持高转速。
- [ ] 提供最长操作时长下的部件温度测量结果及 Thermal/Power 部门确认材料。

## 证据与报告

- 未涉及触发条件：标记为 `已检查-不涉及`，说明未新增部件升级或长时硬件操作。
- 涉及操作且温度更新不中断，或具备完整的 stale 检测、临时散热、fail-safe 和恢复策略：标记为 `已检查-无风险`，列出操作时长、Sensor 更新方式和策略位置。
- 可能阻塞温度更新、继续使用过期读值、缺少临时散热/fail-safe、恢复条件不完整或缺少测试证据：标记为 `当前项有风险`。
- 报告必须写明：操作类型与最长时长、受影响 Sensor/总线/线程、温度过期判定、临时散热动作、fail-safe、退出条件和测试证据。

## 严重级别参考

- 温度长期不更新且旧正常值继续驱动低散热策略，可能造成部件过热或损坏：`[CRITICAL]`。
- 操作期间缺少 fail-safe、恢复失败或并发操作导致风扇提前降速：`[MAJOR]`。
- 策略存在但缺少最长时长测试或 Thermal 确认材料：汇总项标记为 `当前项有风险`；是否形成 `[MINOR]` 问题取决于项目门禁。
