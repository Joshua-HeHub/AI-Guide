# SPX 北向操作审计日志检查

## 触发条件

新增或修改以下任一北向状态变更动作时，必须执行本检查：

- IPMI 配置、控制或 Action 类命令。
- Web API、Web UI 提交的新增、修改、删除或控制动作。
- Redfish `POST`、`PATCH`、`DELETE` 或 Action。
- 用户/权限、网络、固件、电源、硬件、Sensor、日志清理及其他会改变 BMC 或受管设备状态的操作。

纯查询、读取或状态上报且不改变任何状态时，通常标记为 `已检查-不涉及`；涉及敏感信息访问且项目安全策略要求留痕时，仍应纳入审计。

## 审计日志完整性

- [ ] 每个新增或修改的操作入口是否调用统一的审计/操作日志接口？普通 debug、error 或 trace 日志不能替代审计日志。
- [ ] IPMI、Web、Redfish 对同一业务动作是否产生语义一致的审计事件？
- [ ] 成功、业务失败、权限拒绝和关键参数校验失败路径是否都记录操作尝试及结果？
- [ ] 早返回、异步回调和下游失败路径是否会绕过审计记录？
- [ ] 审计日志写入失败是否可观测，是否避免静默丢失关键操作记录？

## 必要字段

- [ ] 操作者身份是否可追溯，例如用户、会话、通道或服务身份？
- [ ] 是否记录来源接口（IPMI/Web/Redfish）及可用的来源信息？
- [ ] 是否记录动作类型、目标对象和必要的变更摘要？
- [ ] 是否记录成功/失败结果、错误码或失败原因？
- [ ] 时间、事件 ID、关联 ID 等字段是否由统一日志设施可靠补充？

## 安全与隐私

- [ ] 不得记录密码、Token、Session ID、密钥、完整证书私钥或其他敏感原值。
- [ ] 配置变更仅记录必要字段名和脱敏摘要，避免把完整请求体直接写入日志。
- [ ] 外部可控字符串是否通过固定格式记录，避免格式化字符串和日志注入风险？
- [ ] 审计记录的访问、清理和轮转是否沿用项目现有安全策略？

## 证据与报告

- 未新增或修改北向状态变更动作：标记为 `已检查-不涉及`，说明仅包含查询/上报或未涉及北向接口。
- 每个操作入口均有完整审计记录且字段、路径和脱敏符合要求：标记为 `已检查-无风险`，列出已检查接口及审计调用位置。
- 缺少审计记录、仅部分接口记录、失败路径漏记、字段不可追溯或日志包含敏感信息：标记为 `当前项有风险`，写明操作入口、缺失路径、后果和修复要求。

## 严重级别参考

- 用户、权限、固件、电源、网络或安全配置等高权限动作缺少审计记录：通常为 `[MAJOR]`。
- 审计日志泄露密码、Token、密钥等凭证：`[CRITICAL]`。
- 低影响操作缺少次要字段，但操作者、动作和结果仍可追溯：`[MINOR]`。
