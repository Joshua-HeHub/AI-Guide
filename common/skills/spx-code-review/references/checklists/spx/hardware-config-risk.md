# SPX 硬件与配置影响检查

## 触发条件

仅当 diff 涉及硬件访问/控制、寄存器、GPIO/I2C/SPI/ADC、设备配置映射、默认值、依赖关系，或可能受 AC Cycle 影响的初始化与持久化逻辑时执行详细检查。未命中时将“硬件/配置及北向接口影响”和“AC Cycle 影响”标记为 `已检查-不涉及`。

## 硬件访问

- [ ] 每次硬件访问是否检查返回值、超时、短传输和设备不存在？
- [ ] 重试次数和间隔是否有上限，失败后是否进入安全状态？
- [ ] 寄存器读改写是否保留无关位，是否影响共享硬件功能？
- [ ] 多线程、多进程或多个接口并发访问时是否正确同步？
- [ ] 输入范围、单位、字节序和硬件规格是否一致？

## 配置与北向接口影响

- [ ] 配置映射、默认值或依赖变更是否影响其他产品配置或功能？
- [ ] IPMI、Web 和 Redfish 对同一设置的读取、写入和错误返回是否一致？
- [ ] 修改硬件状态后，缓存、事件、Sensor 和北向接口是否同步更新？
- [ ] 所有硬件控制变更是否提供相应接口测试或测量结果？

## AC Cycle 影响

- [ ] AC Cycle 后硬件是否按设计重新初始化，状态是否依赖未持久化内存？
- [ ] 配置保存、恢复和默认值覆盖顺序是否正确？
- [ ] 上电时序、设备就绪时间和失败重试是否会改变当前功能？

## 证据与报告

代码命中且检查无风险、证据完整时标记为 `已检查-无风险`。发现硬件/配置影响，或缺少 IPMI/Web/Redfish 测试、测量及 AC Cycle 证据时标记为 `当前项有风险`，写明代码位置、原因和待补材料。

## 严重级别参考

- 可能损坏硬件、绕过安全控制或导致整机不可用：`[CRITICAL]`。
- 硬件操作失败未处理、配置串扰或北向接口行为不一致：`[MAJOR]`。
- 仅缺少验证材料而无确定性缺陷：使用提交者确认项，不虚构问题。
