# SPX 控制流与边界检查

## 适用范围

所有新增或修改的判断、循环、数组、缓冲区、结构体初始化和格式化输出逻辑均加载本清单。

## 判断与循环

- [ ] `if`、`switch` 和条件表达式是否与作者意图一致，正反条件是否写反？
- [ ] 分支是否覆盖零值、负值、最大值、空值和未知枚举值？
- [ ] 循环是否存在明确退出条件，每轮是否保证向退出方向推进？
- [ ] 计数器类型、递增/递减、溢出和错误重试是否可能导致死循环或提前退出？

## 数组与内存复制

- [ ] 数组索引和指针偏移是否在对象有效范围内？
- [ ] 长度单位是否一致，是否混用元素个数与字节数？
- [ ] `memcpy`、`memmove` 等操作是否同时验证源可读长度和目标容量？
- [ ] 长度加法、乘法和类型转换是否可能溢出或截断？
- [ ] 源和目标重叠时是否错误使用 `memcpy`？

## 初始化与循环复用

- [ ] 局部变量、输出参数和结构体是否在使用前初始化？
- [ ] 结构体是完整清零还是逐字段可靠初始化？
- [ ] 循环复用结构体或字符串缓冲区时，每轮是否清理上一轮残留数据？
- [ ] 字符串是否始终保证以 `\0` 结尾？

## 格式化字符串

- [ ] `printf`、`snprintf`、`syslog` 等格式字符串是否合法且不可由外部输入控制？
- [ ] 格式占位符的数量和类型是否与参数完全匹配？
- [ ] `snprintf` 返回值是否检查截断和编码失败？

## 报告要求

只报告有代码证据的问题，并引用具体判断、循环或长度计算位置。边界是否依赖外部协议或硬件规格而无法确认时，标记为 `待提供证据`。

## 严重级别参考

- 越界读写、格式字符串漏洞或可导致 crash 的死循环：`[CRITICAL]` 或 `[MAJOR]`。
- 逻辑分支错误、数据残留或稳定截断：`[MAJOR]`。
- 防御性边界增强且当前无可达故障：`[MINOR]`。
