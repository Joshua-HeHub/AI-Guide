# SPX 并发与调用链影响检查

## 触发条件

出现以下任一情况时加载本清单：

- 修改已有函数的输入、输出、状态、副作用或错误语义。
- 变更全局变量、静态缓冲区、共享内存或跨线程对象。
- 涉及线程、进程、回调、事件循环、锁或 fork。

## 调用链影响

- [ ] 搜索变更函数的所有仓内直接和间接调用者，并检查传入假设、返回值处理和错误路径。
- [ ] 检查变更函数调用的下级函数，确认新的参数、调用顺序和资源所有权符合其契约。
- [ ] 评估原流程中的重试、缓存、状态机、回调和北向接口行为是否仍符合预期。
- [ ] 对仓外调用者、动态绑定或无法解析的函数指针明确标记 `待提供证据`。

## 共享资源

- [ ] 全局变量、共享内存和静态缓冲区是否可能被多个线程或进程读写？
- [ ] 任一写操作是否会使其他读操作看到部分更新、旧值或无效对象？
- [ ] 锁、原子操作、内存屏障或消息传递是否覆盖所有访问路径？
- [ ] 对象生命周期是否可能与异步回调或其他线程交错，形成 use-after-free？
- [ ] fork 与线程混用时，子进程是否继承不可用的锁状态或不需要的 FD？

## 证据要求

报告中列出已检查的关键上游调用者、下游依赖和共享状态。无法遍历的仓外调用、函数指针或运行时注册关系必须说明覆盖限制。

## 严重级别参考

- 竞态、死锁、use-after-free 或跨进程状态破坏：`[CRITICAL]` 或 `[MAJOR]`。
- 调用者错误处理不兼容、行为回退或状态机破坏：`[MAJOR]`。
- 契约或同步说明缺失但尚无可达故障：`[MINOR]`。
