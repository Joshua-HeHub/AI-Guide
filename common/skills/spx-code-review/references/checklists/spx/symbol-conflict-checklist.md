# SPX 全仓符号冲突检查

## 触发条件

当 diff 新增或修改以下任一内容时加载本清单：

- 全局变量或全局数组。
- `extern` 声明或外部链接符号。
- 宏定义、宏名称或构建参数中的 `-D`。

未命中上述条件时，在 Review 事项汇总中标记为 `已检查-不涉及`。完成全仓搜索且无冲突或覆盖缺口时标记为 `已检查-无风险`；发现冲突或搜索范围不完整时标记为 `当前项有风险` 并说明原因。

## 检查步骤

1. 从 diff 提取精确标识符，区分变量名、宏名、类型名和枚举值，不能只搜索名称片段。
2. 在源码、头文件、构建脚本、条件编译文件、生成代码输入及可用的 vendor/第三方头文件中搜索：
   - 定义、声明和引用。
   - `#define`、`#undef` 和 `extern`。
   - Makefile、Kconfig 或编译参数中的 `-D`。
3. 对每个命中项检查：
   - 重复定义或多重外部定义。
   - 声明与定义的类型、长度、限定符是否一致。
   - `static`、`extern` 等链接属性是否一致。
   - 宏重复定义、条件重定义和 `#undef` 是否改变其他模块行为。
   - 不同 `#if`/`#ifdef` 组合下是否可能同时生效。
   - include guard 是否缺失或与其他头文件冲突。
4. 检查平台、厂商和第三方头文件中的同名符号，不能只检查当前模块。

## 证据要求

在 Review 事项汇总的“全仓符号冲突”行中逐个记录标识符、搜索范围、匹配文件和行号、冲突分类及结论；多个标识符使用 `<br>` 分行。不要为符号搜索另建重复章节。

全仓搜索未覆盖生成物、外部库或实际构建参数时，结论必须标记为 `待提供证据`，不得直接判定 `PASS`。

## 严重级别参考

- 导致错误符号绑定、内存布局不一致或运行时行为改变：`[MAJOR]`；可形成安全影响时提升为 `[CRITICAL]`。
- 导致稳定复现的编译或链接失败：`[MAJOR]`。
- 仅命名规范或无行为影响的重复：`[MINOR]` 或 `[NIT]`。
