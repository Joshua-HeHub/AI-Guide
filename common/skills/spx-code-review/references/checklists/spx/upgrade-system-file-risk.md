# SPX BMC 升级与系统文件变更风险检查

## 触发条件

出现以下任一情况时加载本清单：

- 新增或修改 BMC 固件升级、回滚、版本迁移或镜像切换逻辑。
- 新增、修改、移动或删除系统内部文件、目录、软链接或默认配置。

未命中时在 Review 事项汇总中标记为 `已检查-不涉及`；命中时即使没有发现确定性缺陷，也必须标记为 `当前项有风险`、填 `X` 并关联“专项强制提示”类型的 `风险确认 #N`。材料齐全且验证通过时仍保留该提示，不得仅因证据补齐或普通风险关闭自动改为 `V`。

## 检查步骤

- [ ] 升级包、版本、签名、目标分区或目标路径是否可靠校验？
- [ ] 写入、替换和删除是否具备原子性，掉电或进程中断后是否可恢复？
- [ ] 失败回滚是否保留原文件、权限、属主、SELinux/安全属性和软链接语义？
- [ ] 升级前后的配置迁移、默认值和兼容性是否明确？
- [ ] 修改或删除的系统文件是否被启动脚本、daemon、Web、IPMI、Redfish 或其他包依赖？
- [ ] 路径是否可能被外部输入影响，是否存在路径遍历或符号链接替换风险？
- [ ] 空间不足、只读文件系统、校验失败和重复升级是否有明确错误处理？

## 报告要求

命中后将“BMC 升级逻辑与系统内部文件变更”标记为 `当前项有风险`、填 `X` 并关联 `风险确认 #N`；若存在确定性代码缺陷，同时关联 `问题 #N`，不以代码问题替代强制提示。风险确认中列出：

- 触发代码位置。
- 涉及的升级阶段或系统文件路径。
- 兼容性、掉电恢复、回滚和依赖影响，以及已验证范围。
- 实际需要提交者补充的设计或测试证据；材料齐全时写明“无（已提供……）”，不得虚构材料缺口。
- 当前强制保留 `X` 的专项依据；若兼有证据缺口，补齐材料仅关闭该缺口，在本次变更仍命中触发条件、且专项规则未调整时，不自动解除强制提示。是否阻塞合入由项目门禁决定。

## 严重级别参考

- 可导致设备无法启动、固件损坏、配置丢失或升级不可恢复：`[CRITICAL]`。
- 可导致升级失败、功能回退或系统文件状态不一致：`[MAJOR]`。
- 风险证据不足但尚无确定性缺陷：作为风险提示，不虚构问题级别。
