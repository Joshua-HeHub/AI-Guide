# SPX 资源生命周期检查

## 适用范围

所有涉及文件、文件描述符、动态内存、第三方对象、锁、socket、epoll、timer 或其他需显式释放资源的变更均加载本清单。

## 文件与描述符

- [ ] 每次成功打开文件或取得 FD 后，正常返回和所有异常返回路径是否都关闭？
- [ ] `fopen`/`fdopen`、`open`/`close` 等 API 是否使用匹配的关闭方式？
- [ ] 短读、短写、flush 和 `fclose` 失败是否处理？
- [ ] `fork` 后父子进程是否关闭不再需要的 FD？

## 动态内存与第三方对象

- [ ] 每次成功申请是否有唯一且明确的释放责任方？
- [ ] 正常返回、早返回、`goto error` 和嵌套失败路径是否完整释放？
- [ ] `realloc` 是否使用临时指针，分配大小计算是否溢出？
- [ ] cJSON 等第三方库对象的所有权是否明确，创建、引用、分离和删除 API 是否匹配？
- [ ] 循环、重试或长驻路径是否累积内存或造成碎片？

## 锁与同步对象

- [ ] 每次成功加锁后，正常返回和所有异常返回路径是否都解锁？
- [ ] 条件变量、信号量和锁的初始化、销毁顺序是否正确？
- [ ] 是否复制 `pthread_mutex_t` 等锁对象或包含锁的结构体？锁对象禁止按值复制。
- [ ] 多把锁的获取顺序是否一致，是否可能死锁？

## 证据要求

对复杂函数建立“取得资源 → 所有退出路径 → 释放位置”对应关系。未能确认第三方 API 所有权时标记为 `待提供证据`，不能默认释放正确。

## 严重级别参考

- 泄漏可在长驻进程中持续累积、双重释放、锁未释放导致死锁：`[MAJOR]`；可远程触发并造成生产不可用时提升为 `[CRITICAL]`。
- 单次、低影响且有上界的资源清理问题：通常为 `[MINOR]`。
