# SPX IPMI 指令权限变更影响检查

## 触发条件

新增、提高、降低或删除任一 IPMI 指令的权限要求时，必须执行本检查，包括：

- privilege level、role、channel privilege、session requirement 或授权表变更。
- `NetFn/Cmd` 权限映射、命令注册表、handler 权限标志或 OEM 命令权限变更。
- 由认证、授权中间件或公共检查函数间接改变 IPMI 指令可调用性的变更。

未涉及 IPMI 指令权限时标记为 `已检查-不涉及`。

## 指令身份确认

- [ ] 明确变更指令的 NetFn、Cmd、OEM/IANA、LUN、命令常量和 handler。
- [ ] 明确变更前权限、变更后权限、适用通道和会话条件。
- [ ] 检查同一 handler 是否注册到多个 NetFn/Cmd 或被别名、宏、表项复用。
- [ ] 检查权限调整是否只作用于预期指令，避免通用授权函数变更扩大影响面。

## 全仓使用点搜索

必须使用多种标识进行全仓搜索，不能只搜索 handler 名称：

- [ ] 搜索 NetFn/Cmd 数值、宏、枚举、命令名称和注册表项。
- [ ] 搜索 handler、封装函数、消息构造函数和内部 IPMI client 调用。
- [ ] 搜索 Web API、Web UI backend、Redfish handler/Action、内部 REST/RPC 服务和 CLI。
- [ ] 搜索 daemon、定时任务、事件处理、脚本、测试工具、第三方模块及平台适配层。
- [ ] 搜索运行时注册、函数指针、配置映射或生成代码输入；无法解析时标记覆盖限制。

## 影响评估

- [ ] Web、Redfish 或内部服务使用的会话/角色是否满足变更后的 IPMI 权限？
- [ ] 提高权限后，现有功能是否会收到权限拒绝、完成码变化或静默回退？
- [ ] 降低权限后，是否扩大未授权调用面或绕过更高层权限控制？
- [ ] 调用方是否正确处理 `Insufficient Privilege` 等完成码及错误映射？
- [ ] 同一业务动作在 IPMI、Web、Redfish 的权限模型是否保持一致？
- [ ] 是否需要同步修改 Web/Redfish RBAC、内部服务账号、测试用例、文档或升级兼容策略？

## 证据与报告

- 未修改 IPMI 指令权限：标记为 `已检查-不涉及`，说明未命中权限表、注册表或授权逻辑。
- 已完成全仓搜索，未发现 Web、Redfish、内部服务、脚本或其他调用方使用点，无仓外/运行时调用覆盖盲区，且权限调整符合设计、没有越权、必要测试证据完整：才可标记为 `已检查-无风险`，列出指令身份、权限前后值、搜索范围及测试依据。
- Web、Redfish 或其他调用方命中该指令：标记为 `当前项有风险`、填 `X` 并关联 `风险确认 #N`，事项类型为“专项强制提示”。即使已证明调用方兼容且回归测试完整，当前规则下仍保留权限变更影响提示，不得仅凭静态分析、材料补齐或普通风险关闭自动改为 `V`。
- 搜索范围包含无法解析的仓外/运行时调用，或缺少必要的兼容性、权限及回归测试证据：标记为 `当前项有风险`、填 `X` 并关联“证据缺口”类型的 `风险确认 #N`。同一事项兼有调用方命中和材料缺口时可合并说明，不重复展开。
- 发现权限不兼容或越权的代码缺陷时，另关联 `问题 #N`；若同时命中强制提示条件，仍保留对应 `风险确认 #N`。
- 报告必须写明：NetFn/Cmd、权限前后值、命中的调用方、影响范围、已验证的兼容性与测试结果、实际需要补充的回归测试（如有）；材料齐全时明确写明无缺失材料，不虚构缺陷或测试缺口。

## 严重级别参考

- 降低权限导致未授权敏感操作、绕过 RBAC 或权限提升：`[CRITICAL]`。
- 提高权限导致 Web、Redfish、内部服务或自动任务不可用：`[MAJOR]`。
- 调用方兼容时的专项强制提示，或仅缺少回归测试/仓外调用证据：作为 `风险确认 #N`，不虚构代码问题级别；是否阻塞合入由项目门禁决定。
